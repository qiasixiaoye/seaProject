# 海洋要素渲染与数据完善计划

本文档把前端渲染问题、海洋数据分类、陆地掩膜和后续下载高精度 NetCDF 的路线统一收口，作为下一阶段前后端优化依据。

## 当前问题

用户反馈集中在四类：

1. 报告面板和 AI 对话面板互斥后，中间大框的打开逻辑不清晰。
2. 填色图像素感强，粗网格直接铺到地图上，视觉效果不接近 Windy。
3. 粒子流效果不稳定，不应在没有 `u/v` 矢量分量的数据上强行模拟。
4. 陆地上仍可能出现颜色，需要后端掩膜和前端裁剪共同处理。

当前已经完成的基础修复：

| 项目 | 状态 |
| --- | --- |
| 渲染模式按数据类型分类 | 已完成基础版 |
| 只有矢量数据开放粒子流 | 已完成基础版 |
| ETOPO 海陆掩膜 | 已完成后端基础版 |
| 报告面板独立打开 | 已完成基础版 |
| 高精度 `u/v` 海流数据 | 待补充 |
| Windy 风格粒子流 | 待重构 |
| 前端海岸线裁剪 | 待补充 |

## 数据类型分类

后端应给每个变量返回明确的 `render_capabilities`，前端只展示允许的渲染按钮。

| 类型 | 典型变量 | 允许渲染 | 禁用渲染 |
| --- | --- | --- | --- |
| 标量场 | `sst`, `anom`, `salinity`, `ssh`, `chlorophyll` | 填色、等值线、点图 | 粒子流 |
| 地形/水深 | `elevation`, `bathymetry` | 阴影填色、等值线 | 粒子流 |
| 矢量分量 | `u`, `v`, `uo`, `vo`, `ugos`, `vgos` | 分量填色、箭头、粒子流 | 无意义的单分量粒子 |
| 矢量场 | 同一数据集内同时存在 `u/v` | 速度填色、箭头、粒子流、流线 | 只按单变量模拟 |
| 离散点 | 浮标、站点、轨迹 | 点图、轨迹 | 连续填色 |

前端交互原则：

1. 标量数据默认填色。
2. 标量数据可以开启等值线，但等值线不应替代填色。
3. 粒子按钮只在后端确认存在可配对的 `u/v` 变量时启用。
4. 水深数据用独立色带，不复用 SST 的冷暖色带。
5. 陆地区域永远不绘制海洋色块。

## 渲染模式目标

### 1. 填色图

目标不是简单矩形铺色，而是接近海洋产品图：

- 使用连续色带，避免过饱和红绿蓝跳变。
- 对粗网格做双线性插值或三角网插值。
- 网格边界不要显示硬边。
- 透明度随底图层级调整，保留海岸线可读性。
- 陆地像素裁剪为空。

短期实现：

1. 后端继续返回规则网格 `grid`。
2. 前端把格点插值到离屏 Canvas。
3. 颜色映射使用分段连续色带。
4. 基于海陆掩膜或海岸线多边形做 alpha 裁剪。

### 2. 等值线

等值线适合标量场，尤其是 SST、海温异常、海平面高度和水深。

短期实现：

- 使用 Marching Squares。
- 默认 8 到 12 条主等值线。
- 线宽保持细，避免遮挡底图。
- 标签后续再加，第一版只画线。

### 3. 点图

点图用于调试和展示原始采样点。

短期实现：

- 每个有效格点画小圆点。
- 点大小随 zoom 做上限控制。
- 陆地掩膜后的无效点不画。

### 4. 粒子流

粒子流只用于矢量场，不再用标量梯度伪造。

短期实现：

- 需要同一数据集内存在 `u/v` 或可识别配对变量。
- 后端返回 `u_grid`、`v_grid`、`speed_grid` 和统计值。
- 前端每帧按当前位置双线性采样矢量，推进粒子。
- 粒子颜色按速度或方向映射。
- 粒子尾迹使用低 alpha 衰减，不闪屏。
- 小地图不重复高频动画，默认显示静态缩略或降帧。

## 陆地掩膜方案

后端已经加入 ETOPO 派生海陆掩膜。下一步需要把职责分清：

| 层 | 责任 |
| --- | --- |
| 后端 | 在返回数据前过滤陆地格点，把陆地点设为 null，并返回 `land_mask_applied` |
| 前端主图 | 对 null 像素保持透明，不做跨陆地插值 |
| 前端小地图 | 复用主图渲染结果或降采样，不单独重新插值 |
| 测试 | 对台湾、菲律宾、中国东南沿海三个 bbox 做固定回归 |

需要重点修复的是“海上格点颜色扩散到陆地”。即使后端已经把陆地点设为空，前端插值时也不能让有效海点跨过 null 区域补色。

## 高精度 NetCDF 数据路线

已核对的候选数据源：

| 来源 | 适合用途 | 说明 |
| --- | --- | --- |
| NOAA OISST v2.1 | SST 标量填色、等值线 | NOAA NCEI 说明 OISST 是 0.25 度日尺度全球规则网格产品，适合稳定演示。 |
| HYCOM | 海流 `u/v`、粒子流 | HYCOM 数据服务提供全球分析和 NetCDF Subset Service，可用于下载指定区域海流分量。 |
| Copernicus Marine | 海流、温盐、海平面、生态变量 | 官方 Marine Data Store 和 Toolbox 支持 NetCDF 子集下载，适合后续扩充多要素。 |
| GEBCO/ETOPO | 地形、水深、海陆掩膜 | 用于水深渲染和掩膜，不用于粒子流。 |

短期建议：

1. 保留当前 OISST 小样本作为快速测试数据。
2. 新增一个台湾到吕宋海峡区域的 HYCOM 或 Copernicus `u/v` 子集，用于真实粒子流。
3. 新增一个高分辨率 SST 子集，用于优化填色图。
4. 所有下载脚本固定输出到 `data/nc_uploads`，并生成数据说明 JSON。

下载脚本设计：

```text
scripts/
  download_ocean_sample.py
    --source oisst|hycom|copernicus
    --bbox 117,127,18,26
    --date YYYY-MM-DD
    --variables sst,uo,vo
    --out data/nc_uploads/<name>.nc
```

注意：Copernicus Marine 可能需要账号和 token。脚本应支持环境变量注入，不把凭据写入仓库。

## 后端 API 扩展

现有 `/api/ocean/query` 可以继续兼容标量查询。新增矢量场时建议扩展而不是破坏旧结构。

建议响应字段：

```json
{
  "dataset": "hycom_luzon_current",
  "variable": "speed",
  "data_type": "vector",
  "render_capabilities": ["fill", "contour", "vector", "particles"],
  "grid": [[0.12, 0.18]],
  "u_grid": [[0.03, 0.08]],
  "v_grid": [[-0.02, 0.04]],
  "mask_grid": [[1, 1]],
  "bbox": { "west": 117, "east": 127, "south": 18, "north": 26 },
  "units": "m/s",
  "land_mask_applied": 37
}
```

兼容规则：

1. 标量数据不返回 `u_grid/v_grid`。
2. 只有同时存在 `u_grid/v_grid` 时，`render_capabilities` 才包含 `particles`。
3. `mask_grid=0` 的位置前端必须透明。
4. 统计值只基于有效海洋点计算。

## 前端交互完善

### 面板逻辑

建议把右侧 AI 对话、报告、大图分析做成明确状态机：

| 状态 | 触发 | 行为 |
| --- | --- | --- |
| `assistant` | 点击 AI | 打开 AI 对话 |
| `report` | 点击报告 | 打开报告面板 |
| `analysis` | 点击地图结果或分析按钮 | 打开中间大框 |
| `collapsed` | 点击关闭 | 收起右侧面板，但保留浮动入口 |

中间大框不应依赖 AI 对话是否打开。即使用户关闭 AI，也应能通过固定入口重新打开报告或分析结果。

### 渲染按钮

按钮按能力动态启用：

```text
填色：标量/矢量都可
等值线：标量/速度场可
点图：所有格点数据可
粒子：仅矢量场可
箭头：仅矢量场可
```

禁用按钮要显示原因，例如“当前变量没有 u/v 分量”。

## 验收标准

1. 标量 SST 数据切到粒子模式时，按钮应禁用或提示原因，不再画伪粒子。
2. `u/v` 海流数据切到粒子模式时，粒子应沿矢量场连续运动，无整块贴图、无右下角闪烁。
3. 台湾、福建、菲律宾陆地区域不出现海洋填色。
4. 小地图不出现高频闪烁。
5. 报告面板关闭后，用户仍能通过固定入口打开中间大框。
6. `node --check frontend/assets/app.js` 通过。
7. `/api/ocean/query` 对标量和矢量样例均返回稳定结构。
